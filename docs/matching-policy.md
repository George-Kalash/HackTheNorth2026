# Matching and review policy

Candidate scores rank wording, entities, event timing and supported Fed outcome buckets; they do not certify payouts. `EXACT`, `SYNTHETIC_EQUIVALENT`, `RELATED`, `REJECTED` are independent of `UNREVIEWED`, `APPROVED`, `REVOKED`.

The Fed seed URLs fetch their actual October 2026 events and full outcome/rule sets. The code does not substitute a different meeting if an event is missing. A >25 bp bucket and a 50+ bp bucket are merely candidates: rounding, target-rate definition, cancellation, emergency actions and observation windows may differ. Parser fields left unresolved are listed explicitly. No title-only matching can enter the verified scanner.

An approval requires current rule hashes, an audit reason, and seven evidence statements: event identity, observation window, variable/baseline, threshold/inclusivity, authority, cancellation/void/disputes and currency/payout. A local reviewer can attest semantic equivalence after reading both source rules. The system records that attestation rather than claiming automated legal verification. Changed source text revokes review and retains the prior history.

A synthetic mapping requires an explicit, allegedly exhaustive state matrix and a separate coverage explanation. Exact arithmetic validates replication before saving; settlement review is still required. The Senate regression demonstrates that Democratic Senate control needs DD + RD (first letter House, second Senate), not only DD. OTHER is a required state; omitting it or double-counting DD fails validation.

Search is bounded, not an exchange-wide discovery engine: top six Kalshi series, up to three cursor pages each, then 20 ranked events; first 20 Polymarket search events. URL imports bypass keyword discovery. Generic import loads up to three counterpart events. The exact supplied Fed seeds form a candidate lookup shortcut, never a preapproved match.
